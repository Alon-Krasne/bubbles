# Educational Game Prototypes

The prototype directory contains the mixed-game trail and its playable vertical slices.

## Unified World Map

Open `http://127.0.0.1:5173/` after starting the dev server. The root entrypoint opens the world map; hosted Memory Garden and Listening Shop sessions continue to use `index.html` with the validated world-map context.

The map mixes Memory Garden, Listening Shop, and Magic House across 15 playable stages. Completed and current stages can be replayed, saved stars never decrease, and only completing the current frontier advances the character.

All route and difficulty configuration lives in `shared/trail-catalog.mjs`. Its factories expose pair count and vocabulary pools for Memory Garden, customer count/shelf size/order mode/item pools for Store, and request pool/request count/drawer size/help limits for Magic House. Per-profile coverage decks exhaust each configured Memory and Store pool before repeating words. See `docs/TRAIL_CATALOG.md` for the extension workflow.

The root opens with a profile chooser. Profiles have a stable ID, name, one of four character sprites, and an English or Hebrew learning direction. Profiles can be created, edited, selected, and deleted from the same game-styled flow; route progress remains attached to the stable ID when the visible profile changes.

Memory Garden and Listening Shop run inside the trail's hosted activity shell. Their normal standalone navigation remains unchanged, while hosted completion and exit events use the shared same-origin protocol in `src/hostedActivity.ts`. English-learning activities use spoken English with image choices and keep English answer cards free of drawings. Hebrew-learning activities use written Hebrew prompts and choices without answer images or pre-answer speech.

## Magic House

Open `http://127.0.0.1:5173/prototype/magic-house.html` to test the bedroom directly.

The room contains six cumulative English/Hebrew placement requests, profile-aware Google TTS, tap and pointer-drag placement, graduated help, non-punitive feedback, success toasts, and completion stars. Its full-room environment is generated with Nano Banana Pro (`gemini-3-pro-image`) from the original bedroom reference; it keeps the calibrated furniture layout while extending the scene to the frame edges.

Pointer dragging uses one gesture path across mouse and touch. Failed drops always remove the drag ghost and return the tray object to rest. Drop zones and final object positions share the calibrated room map in `shared/magic-house-room.mjs`. Selecting or dragging an object gives every destination the same projected glow and learning-language label; English labels include a small Hebrew location gloss, while the second help step highlights the exact requested destination.

When opened from the trail, Magic House receives the active profile and stage context through its URL, locks profile switching, and posts either a verified completion result or an explicit exit back to the same-origin trail. Direct access keeps the existing replay flow.

The committed WAV files are generated by Gemini 3.1 Flash TTS Preview. To regenerate all English and Hebrew request recordings:

```bash
GEMINI_API_KEY=... bun run generate:magic-house-tts
```

Memory Garden and Store vocabulary use committed Google TTS clips so pronunciation does not depend on the browser or device. Regenerate the complete routed vocabulary set with:

```bash
npm run generate:vocabulary-tts
```

The generator requires `ffmpeg`. It reads `GEMINI_API_KEY` when set, or the Google API key already loaded in OpenCode. A committed generation manifest invalidates clips whenever the transcript, model, voice, or pacing profile changes.
